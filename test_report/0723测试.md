### 4. 前进实机测试跳过 turn-only 输出

模型对 `Move forward slowly.` 的第一帧经常先输出离散转向 `[2,2,2,2]` 或 `[3,3,3,3]`。为了验证“明确前进指令”的前进闭环，新增了跳过 turn-only 的测试开关。

修改 `scripts/realworld/internnav_direct_control_client.py`：

```text
新增 --skip-turn-only-motion
实机模式下遇到 step.kind="spin" 时只发布零 Twist
记录状态 SKIP_TURN_ONLY
继续等待下一次推理
```

修改 `scripts/realworld/run_minimal_closed_loop.sh`：

```text
新增 SKIP_TURN_ONLY_MOTION=1
```

该开关不会把转向动作改写成前进动作，只是跳过不符合前进测试目标的 turn-only 输出。

### 5. Nav2 / collision monitor 运行时安全参数

今天发现 `/livox/lidar` 原始点云包含大量 `(0,0,0)` 和自车近点，导致 collision monitor 的 `CircleStop` 被误触发。

诊断依据：

```text
collision_monitor 日志: Robot to stop due to CircleStop polygon
livox_frame -> moz1/base_link: x=0.241, y=-0.023, z=0.044
原始点云中大量近点落入 0.55 m 停止圆
```

处理方式：没有关闭 collision monitor，而是过滤自点并保留 stop / slowdown 区。

最终运行时参数：

```text
CircleStop.radius = 0.55
CircleLimit.radius = 0.65
CircleLimit.slowdown_ratio = 0.10
pointcloud.min_height = 0.45
pointcloud.max_height = 1.8
velocity_smoother.max_velocity = [0.12, 0.08, 0.25]
```

## 当前仍存在的问题

1. ROS 2 CLI 的 lifecycle、param、action 查询偶发超时或挂住。

   今天 `preflight_internnav_nav.sh --motion` 和 `configure_safe_nav2_motion.sh` 曾被 ROS CLI discovery / service 调用卡住影响。后续建议把关键检查改成 rclpy 探测脚本，减少对 CLI service 的依赖。

2. `/nav_executor` 仍有两个同名节点。

   当前真实运动链路中允许 `ALLOW_LEGACY_IDLE_STACK=1`，并用 `/nav_task_status=0` 确认 idle。后续建议从宿主机或启动端彻底清理重复 legacy 节点。

3. collision monitor 的运行时参数需要固化。

   今天的可用参数在 `/tmp/internnav_nav/spirit_params_no_filters.yaml` 中验证通过。后续应整理进正式 Y03 Nav2 配置，避免重启后丢失。

4. `pixel_goal_valid` 在部分结果中为 false。

   模型输出的 pixel 坐标和客户端用于校验的 `384x384` 尺寸存在不一致。trajectory 可用且本次控制依赖 trajectory，但 pixel_goal 可视化/坐标校验后续需要统一。

5. `Move forward slowly.` 第一帧常出现离散转向。

   今天通过 `SKIP_TURN_ONLY_MOTION=1` 跳过 turn-only 输出后完成前进闭环。后续可以继续优化 prompt、模型历史 reset 或动作选择策略，让前进指令更稳定地产生 forward trajectory。
